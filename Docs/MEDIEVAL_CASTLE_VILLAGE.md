# Medieval eastern Mediterranean castle village — art and construction review

Branch base: `pvt/parametric-architectural-finishes` at `b4f69d4b78ccf30c10d90ffb20001e24b25a51a0`. This is an authored **reference scene** for manual visual and functional review. It is not a gameplay command that automatically builds a town and it is not a performance certification.

## Composition

The 80 m landscape contains one square fortified castle with four corner towers, crenellated curtain walls, an arched passage and timber gate leaves, an interior keep, dome, stairs and courtyard; one trading hall with three shop openings, arches, counters and awnings; and six residences in three authored proportions along the lane. A paved approach and market square connect the stronghold to the commercial area. The visual language draws on medieval eastern Mediterranean stone settlements: light sandstone/plaster masonry, ceramic roofs, timber doors and shutters, and dry natural ground. The exact historical period and authenticity must be reviewed by a human; this scene is not labeled as an archaeological reconstruction.

Every wall, slab, roof, arch, tower section, counter, stair and crenellation is a `PieceData` with stable `PieceId`. Openings and their linked frames, lintels, glass and eaves are stored in the host `PieceData`. The authored trading hall and castle do not become indivisible prefabs. Vegetation and rocks are independent environmental objects, explicitly outside the construction model. The small CC0 PBR/LOD set is reused from the previous reference branch; no new external license is introduced. Asset provenance remains in `Docs/PVT_FREE_ASSETS_MANIFEST.csv`.

`PvtMedievalVillageScenario.Build()` is deterministic. It reuses `PvtVisualCityScenario.BuildResidenceAt()` for six individual parametric residences and adds castle and trading hall recipes. `PvtFreeAssetsReferenceRunner` now has an opt-in village mode; the original one-house scene remains its default. The village is saved separately as `aedifica_castle_village.pvt2` under `Application.persistentDataPath`. Selection, move, resize (where valid for the selected piece), material change, delete, undo/redo and save/load use the same `ConstructionWorld`, `ConstructionCommandHistory`, `PvtChunkVisualEngine` and `Pvt2Snapshot` path as the reference house.

## Unity Windows procedure

1. Preserve any existing Windows modifications and stashes. From a clean checkout run:

   ```powershell
   git fetch origin pvt/medieval-castle-village
   git worktree add C:\Projetos\AEDIFICA-MEDIEVAL origin/pvt/medieval-castle-village
   cd C:\Projetos\AEDIFICA-MEDIEVAL
   git rev-parse HEAD
   ```

   If the target folder exists, inspect it and choose another empty path rather than overwriting it. Open the new worktree in Unity **6000.6.4f1**.
2. Run **Tools → Aedifica → Medieval Castle Village → Create Village Scene**. The builder prepares persistent URP materials and CC0 prefabs, creates `Assets/Game/Scenes/PvtMedievalCastleVillage.unity`, and adds it to the build scene list. It refuses to overwrite an existing scene. The scene file is generated by Unity because the remote environment lacks Unity Editor; review and version the generated scene and asset references after successful local validation.
3. Open the new scene, enter Play Mode and use Game View. Review the five fixed camera buttons: castle gate, market arcade, residential lane, castle courtyard and village panorama. Click **Capture 5 views** to write genuine Game View PNGs to `Application.persistentDataPath`. No external render stands in for Unity screenshots.
4. Select a castle wall, a house wall, an arch and a roof; try Move +X, Resize +X where supported, Change material, Delete, Undo/Redo, Save/Load and linked-finish controls. Confirm that linked features move with their host and that independent timber gate/door leaves remain individual pieces. Inspect the Console for import, geometry and shader errors.
5. Run all EditMode and PlayMode suites, including `PvtMedievalVillageTests` and `PvtMedievalVillagePlayModeTests`. Only then build a Windows x64 visual review Player if desired. Review from the Game View/Player on the Lenovo LOQ before expanding or benchmarking.

## Limits and next review

The castle and market are modular block, arch, wall and roof compositions using the present parametric grammar; they are intentionally **not** imported ready-made castles. Material repetition, tower silhouette, stalls, gate leaf attachment, interior access, roof joins, vegetation layout and lighting need manual art review. Gate leaves, counters and some house door elements are independent `PieceData`, so moving a wall does not automatically move them. The linked-frame system covers opening surrounds and roof eaves, not every attached decoration. The environment remains small and bounded; this scene makes no claim about 80–100 FPS or large-city scaling. The reference must be reviewed in Unity before any aesthetic or performance approval.
