# ADR 0016 — E1b: spatial index and reversible piece commands

## Decision

`ConstructionWorld` remains the single logical owner of `PieceData`. Each effective `Create`, `Update`, or `Delete` applies its `ConstructionChangeSet` to an incremental `ConstructionSpatialIndex` and then emits `Changed` and `ChunksInvalidated`. Rejected and unchanged operations do neither. The default chunk edge is 64 metres and can be supplied to the world constructor. A piece has one ID; its rotated world AABB may register that ID in several 3D chunks. Query results deduplicate IDs and test AABB intersection before returning them. `QueryNearby` additionally tests distance to the AABB. These are broad-phase queries; a later narrow phase must test the actual mesh or collider if needed.

Chunk cells use half-open intervals `[n * size, (n + 1) * size)`. A positive-volume AABB ending exactly on a cell boundary does not enter the next cell. An AABB starting on that boundary does. Negative coordinates use mathematical floor, not integer truncation. A piece's world AABB comes from `ConstructionChangeSet.WorldBounds`, which encloses its rotated parameter envelope. This can overinclude empty volume for curved or open shapes; it must not omit their envelope.

A change invalidates the union of its old and new chunk memberships. An update within one chunk emits one chunk, even if only material changes. Moving a piece invalidates its old and new chunks, without scanning other pieces. Listeners can use `ConstructionInvalidation.Change` for the exact before/after bounds and state. The index is updated before either notification, so listeners observe the new world state. E1b does not rebuild combined meshes or change `PieceView` rendering.

`ConstructionCommandHistory` stores only changed `ConstructionChangeSet` snapshots. Its default limit is 256 operations; the lab's serialized `historyCapacity` can override it. `Create`, `Update`, and `Delete` record successful changes. `TryUndo` and `TryRedo` replay the inverse/forward world mutation through the same world API, which also updates the index and emits invalidation. A new effective command after undo drops the redo tail. Rejected and no-op commands preserve the history, including any redo tail. Before replay, history checks that the target piece still matches the expected snapshot; a conflicting external world mutation makes replay return false. Existing `PieceData` values and their opening views are immutable, so history does not copy the entire world. `ConstructionLabBlocks` synchronizes `PieceView` for a successful replay. There are no Undo/Redo keys or buttons in E1b.

## Limits and next verification

Index storage and mutation cost are proportional to the number of intersected chunks. Very large pieces or extremely small configured chunks can consume substantial memory and time. Coordinate values beyond the supported integer cell range are rejected before changing the world. The index does not yet accelerate snap, selection, or rendering; those paths retain their existing behavior. The command history covers individual piece operations only, without transactions or composite commands. The Lenovo LOQ homologation should run EditMode and PlayMode suites, repeat ConstructionLab creation, transformation, snap, materials, selection, and compare PerformanceLab S0/S1 measurements with E1a using the established build procedure. No performance claim follows from these logical tests.
